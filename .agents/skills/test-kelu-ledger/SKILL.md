# 可噜记账测试

严格以 `D:\A vibe coding\黑马记账app` 内的实际代码、`codex.md` 产品约定和当前 Git 改动为依据，为可噜记账补充并执行可靠测试。不要把“写完测试”当成“测试通过”。

## 开始前

1. 确认当前目录是可噜记账项目，并读取 `codex.md`、`package.json`、相关源码和现有测试。
2. 执行 `git status --short` 和 `git diff --stat`，区分用户已有改动与本次测试改动；不要覆盖无关改动。
3. 阅读 [references/test-strategy.md](references/test-strategy.md)，根据本次改动选择测试层级和重点风险。
4. 用一句通俗中文说明将检查什么。若任务需要工具调用，在执行期间保持简短进度更新。

## 确定测试范围

把待验证行为分为以下层级，并在报告中如实标注：

- **单元测试**：独立函数、解析、校验、金额和统计计算等，不访问真实文件或数据库。
- **集成测试**：SQLite 约束、事务、备份恢复、分类关联和数据迁移等多个组件协作行为。
- **界面或安装验证**：Electron 界面点击、动图、主题、安装和卸载。普通 Vitest 结果不能证明这些行为正确；未实际操作时列为“未验证”。

优先测试本次新增或修改的行为、错误输入、边界值和可能被破坏的旧功能。不要为追求数量创建没有业务意义的测试。

## 创建测试

1. 沿用 Vitest 和项目现有测试风格，测试文件使用 `*.test.ts`。
2. 使用用户能理解的中文 `describe` 和 `it` 名称，名称应描述业务结果。
3. 每个测试遵循“准备数据、执行行为、验证结果”，断言具体可观察结果。
4. 覆盖适用的正常、边界、错误、空值、重复和回归场景。
5. 金额始终验证整数分与人民币显示规则；不得用浮点近似掩盖金额错误。
6. 日期测试使用固定时间，不依赖当前日期、执行顺序、网络或随机外部状态。
7. SQLite 测试只能使用系统临时目录中的独立测试数据库；结束后关闭连接并清理临时文件。禁止打开、复制、修改或删除用户实际数据库。
8. 不在测试中写入 `release/`，不调用真实备份文件，不启动安装程序，不连接外部服务。
9. 不为了让测试通过而删除有效断言、降低断言精度、跳过失败测试或把错误结果改成期望结果。

如果发现产品需求不明确，或修复方式会明显影响体验、隐私、成本或维护方式，先按 `codex.md` 提供方案并等待用户选择。普通低风险测试实现细节可直接采用成熟做法。

## 执行验证

在 Windows PowerShell 中使用 `npm.cmd`，避免系统执行策略阻止 `npm.ps1`。

先运行受影响测试；完成后必须运行完整验证：

```powershell
npm.cmd run typecheck
npm.cmd test
```

只有用户明确要求或改动涉及构建配置、Electron 入口、资源导入时，才额外运行：

```powershell
npm.cmd run build
```

不得仅根据代码阅读声称测试通过。记录实际命令、退出状态、测试文件数、测试数量、通过、失败、跳过和耗时。若命令因环境问题无法执行，明确写“未执行”或“被阻塞”。

## 处理失败

1. 保留原始失败信息并定位到具体测试和代码行为。
2. 区分产品代码缺陷、测试错误、需求歧义和环境故障。
3. 用户只要求测试或报告时，不擅自修改产品代码；说明问题、影响和证据。
4. 用户明确要求修复时，进行最小范围修复，重新运行受影响测试及完整测试。
5. 失败测试不得被静默跳过。确需跳过时必须获得合理依据，并在报告中列出原因和风险。

## 输出中文测试报告

每次实际测试后，在回复中使用以下固定结构；没有内容的项目写“无”，不要捏造数据：

```markdown
测试结论：通过 / 未通过 / 部分验证 / 被阻塞

- 测试目标：
- 代码范围：
- 新增或修改的测试：
- 执行命令：
- 执行结果：测试文件 X，测试 X，通过 X，失败 X，跳过 X
- 发现的问题：
- 已验证内容：
- 未验证内容：
- 建议：
```

测试失败时补充测试名称、预期结果、实际结果、可能影响和下一步建议。涉及文件时提供可点击的本地文件链接。除非用户明确要求，不要额外生成永久测试报告文件。

## 完成标准

仅当以下条件都满足时，才可以报告测试任务完成：

- 测试与产品规则一致并包含关键边界情况；
- 新测试真实执行且结果已记录；
- 完整类型检查和完整测试已执行，或明确说明无法执行的原因；
- 没有接触真实用户数据库和个人账目；
- Git 状态已复查，本次只包含预期测试相关改动；
- 报告明确区分已验证和未验证内容。
