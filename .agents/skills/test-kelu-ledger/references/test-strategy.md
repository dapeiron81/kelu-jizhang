# 可噜记账测试策略

## 项目基线

- 运行平台：Windows。
- 技术栈：Electron、React、TypeScript、SQLite、Vitest。
- 单元测试：`src/shared/*.test.ts`。
- 数据库集成测试：`src/main/*.integration.test.ts`。
- 完整类型检查：`npm.cmd run typecheck`。
- 完整自动化测试：`npm.cmd test`。
- 构建验证：`npm.cmd run build`。

## 代码区域与主要风险

| 区域 | 适合的测试 | 重点风险 |
| --- | --- | --- |
| `src/shared/logic.ts` | 单元测试 | 金额换算、零值、负数、小数位数、月度统计、上月为零 |
| `src/shared/csv.ts` | 单元测试 | UTF-8、中文、逗号、引号、换行、空行、错误列和重复记录 |
| `src/shared/types.ts` | 类型检查 | 主进程、预加载和界面之间的结构不一致 |
| `src/main/index.ts` | 集成测试 | SQLite 约束、事务回滚、分类关联、备份恢复、数据迁移和路径切换 |
| `src/preload/index.ts` | 类型检查与接口验证 | 暴露多余系统能力、接口参数或返回值不一致 |
| `src/renderer/src/App.tsx` | 抽离逻辑后做单元测试；界面需另行验证 | 表单校验、筛选、状态同步、错误提示和用户操作流程 |
| 打包配置与资源 | 构建、安装和人工验证 | 安装目录、应用名称、图标、资源缺失、首次启动数据库 |

## 必须保护的业务规则

- 记录人民币收入和支出，金额大于零且最多两位小数，以整数分存储；旧账目升级后保持为支出。
- 收入与支出使用相互独立的两级分类，结余等于收入减去支出。
- 二级分类必须属于所选一级分类。
- 分类改名、停用或排序不能破坏历史账目。
- 已使用分类不能直接删除；删除分类不能删除历史账目。
- 统计必须按目标月份准确汇总，并正确处理无上月数据和跨年月份。
- CSV 导入前应区分有效、重复和错误记录；写入失败必须整体回滚。
- 完整备份包含账目、分类和设置；恢复失败不能损坏当前数据。
- 更改数据位置时，校验成功后才能切换，原数据库应保留。
- 新用户首次启动创建空数据库，不携带开发者个人数据。

## 测试数据安全

- 真实数据库通常位于 `%APPDATA%\可噜记账\kelu-ledger.db` 或用户自选目录，任何自动化测试都不得访问它。
- 测试数据库使用 `mkdtempSync(join(tmpdir(), 'kelu-ledger-test-'))` 创建隔离目录。
- 每个测试关闭数据库连接，并在 `afterEach` 中删除隔离目录。
- 不把 `.db`、`.db-wal`、`.db-shm`、备份、CSV、`release/` 或 `node_modules/` 加入 Git。

## 不能由普通单元测试证明的内容

- Electron 窗口能否正常启动和响应真实鼠标、键盘操作。
- GIF 是否循环播放、圆形裁剪是否正确、浅色和深色视觉是否正常。
- Windows 安装、安装目录选择、卸载和 SmartScreen 行为。
- 用户自选数据目录在不同磁盘、权限和断开设备情况下的真实表现。

没有进行对应的启动、操作或安装验证时，报告中必须将这些内容列为“未验证”。
