# 代码注释检查

只用于“可噜记账”项目。把注释当作帮助后来维护者理解“为什么这样做、会产生什么结果”的说明，不把注释行数当作唯一质量标准。

## 开始检查

1. 读取 `codex.md`、`package.json`、相关源码和现有测试，理解真实产品规则。
2. 执行 `git status --short` 和 `git diff --stat`，保护用户已有改动。
3. 明确检查范围；用户没有指定时检查 `src/` 中由项目维护的 `.ts`、`.tsx`、`.js`、`.jsx`、`.css` 和 `.html` 文件。
4. 读取 [references/comment-standard.md](references/comment-standard.md)，使用同一标准评估所有文件。
5. 默认只检查并报告。只有用户明确要求补充或修正注释时，才编辑文件。

## 统计注释密度

运行：

```powershell
python -X utf8 .agents\skills\comments-check\scripts\comment_density.py src --target 0.30
```

将“有效注释行 ÷（有效注释行 + 代码正文行）”与 30% 目标比较。空行不参与计算；代码行尾的短注释按代码行处理，防止一行重复计数。

把脚本结果作为筛查信号，不直接作为最终结论。脚本不能理解注释真假，也可能受字符串中的注释符号影响；必须继续人工核对语义。总比例达到 30% 但关键函数没有注释时仍判为不合格；比例不足时必须指出具体缺口，不建议用废话凑数。

## 检查完整度

逐文件检查以下对象：

- 每个具名函数、导出函数、组件、Hook、事件处理函数和具有业务作用的回调；
- 金额、日期、分类、统计和 CSV 处理逻辑；
- SQLite 表结构、约束、事务、备份、恢复和数据位置迁移；
- Electron 主进程、预加载安全边界和跨进程接口；
- 不直观的分支、兼容处理、回滚、容错和安全限制。

每个函数至少应有一段紧邻的说明，解释用途和结果。适用时继续解释输入、返回值、副作用、业务限制、失败行为和选择这种实现的原因。简单导入、括号、纯样式常量和一眼可见的赋值不要求逐行注释，但重要代码段必须有上下文说明。

## 检查准确性

沿实际执行路径核对每条注释：

1. 比较注释描述的输入、输出、单位、条件、失败处理和副作用与代码实际行为。
2. 特别核对人民币“元/分”、日期时区、分类删除限制、事务回滚、备份恢复和数据路径。
3. 找出已经过期、只描述旧实现、夸大保证或与函数名称和测试冲突的注释。
4. 无法从代码、测试或产品文档证实的承诺标为“无法验证”，不要自行猜测。

错误注释比缺少注释风险更高。可能导致维护者改坏数据、隐私或金额逻辑的错误注释标为严重问题。

## 检查小白可读性

以第一次接触项目、不了解 Electron、React 或 SQLite 的读者为标准：

- 先讲功能效果，再出现技术名词；
- 技术名词首次出现时用一句日常语言解释；
- 说明“为什么”和“不这样做会怎样”，不要只把代码翻译成中文；
- 使用短句、具体名词和明确因果，避免“处理一下”“相关数据”“正常逻辑”等含糊表达；
- 金额、时间、文件路径和数据覆盖必须写清单位及影响；
- 不写只有作者自己理解的缩写、玩笑或无上下文代词。

## 修改注释时

仅在用户明确要求修改时执行：

1. 只改注释，除非用户另行授权修改产品代码。
2. 优先补充关键函数和高风险代码，不机械地每隔几行插入注释。
3. 保持注释与函数紧邻，避免大段说明漂移到无关代码前。
4. 不删除仍然准确且有价值的用户注释。
5. 修改后重新运行密度脚本、`npm.cmd run typecheck` 和 `npm.cmd test`，确认注释编辑未意外破坏代码。

## 输出检查报告

使用以下结构，没有内容时写“无”：

```markdown
注释检查结论：通过 / 需要改进 / 不通过 / 被阻塞

- 检查范围：
- 有效代码行：
- 有效注释行：
- 注释密度：X%，目标至少 30%
- 缺少注释：
- 注释与代码不匹配：
- 小白阅读问题：
- 写得好的注释：
- 未检查内容：
- 建议修复顺序：
```

每个问题提供文件和行号、相关函数或代码段、问题类型、通俗原因和推荐写法。按以下优先级排序：错误或误导注释、核心代码缺少注释、小白无法理解、普通密度不足。

## 完成标准

只有满足以下条件才报告检查完成：

- 密度脚本已实际运行，或明确说明无法运行的原因；
- 已逐个核对检查范围内的函数和核心代码；
- 已比较注释与代码、测试及 `codex.md` 的一致性；
- 报告给出可定位的证据，不只给出总分；
- 明确区分缺少注释、错误注释和难懂注释；
- 复查 Git 状态，默认没有修改产品文件。
