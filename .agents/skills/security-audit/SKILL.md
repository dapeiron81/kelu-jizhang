# 可噜记账安全审计

只对用户授权的“可噜记账”项目执行防御性审计。默认只读取项目文件并输出脱敏报告，不运行攻击载荷，不访问真实账目数据库，不自动修复、提交或推送代码。

## 开始审计

1. 读取 `codex.md`、`package.json`、`.gitignore`、相关源码、配置和测试，理解产品的数据边界。
2. 执行 `git status --short`、`git diff --stat` 和 `git ls-files`，区分已跟踪、未跟踪和忽略文件。
3. 阅读 [references/threat-model.md](references/threat-model.md)，按可噜记账的资产、入口和信任边界选择检查重点。
4. 明确检查范围。用户未指定时检查项目维护的源码、配置、脚本和文档；跳过 `node_modules/`、`out/`、`release/`、`dist/`、`.git/` 及真实 `.db` 数据文件。
5. 不把任何疑似秘密完整复制到聊天、报告、日志或新文件。只报告文件、行号、秘密类型和脱敏说明。

## 扫描敏感信息

运行本地启发式扫描：

```powershell
python -X utf8 .agents\skills\security-audit\scripts\secret_scan.py .
```

脚本用于发现高风险候选项，不代表最终结论。继续人工检查：

- 密码、API Key、访问令牌、Cookie、私钥和证书私钥；
- 带用户名和密码的数据库或服务连接地址；
- `.env`、JSON、TOML、YAML、构建配置、测试数据、示例和日志；
- Electron 打包配置是否把秘密、数据库、备份或调试文件装进安装包；
- `.gitignore` 是否排除 `.env`、数据库、备份、日志和本地配置；
- 源码是否把秘密写入界面、错误提示、控制台或导出文件。

遇到疑似真实秘密时立即停止展开内容，只提供位置和处置建议。不得尝试使用、验证或连接该凭据。当前工作区无问题不等于 Git 历史无问题；未检查历史时必须在报告中说明。

## 检查注入风险

### SQL

- 查找字符串拼接、模板字符串或用户输入直接进入 `SELECT`、`INSERT`、`UPDATE`、`DELETE`、`PRAGMA`、`VACUUM` 和 `exec`。
- 确认普通数据值使用 SQLite 预编译语句和绑定参数。
- SQL 不支持参数化的表名、列名和路径必须使用固定映射、严格白名单或可靠转义；仅检查非空不等于安全。
- 确认 CSV、备注、商家、分类、日期和自选路径不能改变 SQL 结构。
- 事务失败必须整体回滚，不能留下半批数据或损坏当前数据库。

### 命令、路径和内容

- 查找 `exec`、`spawn`、shell 字符串、动态脚本和外部程序调用，检查用户输入是否能改变命令结构。
- 检查文件选择、备份、恢复、CSV、自选数据目录和迁移路径是否防止目录穿越、意外覆盖、符号链接绕过和写入非预期位置。
- 检查把外部内容插入 HTML 的位置，避免 `innerHTML`、不可信 URL、脚本协议和 Electron 导航造成代码执行。

只使用静态分析和安全的最小验证。不要构造会删除、覆盖、联网、执行系统命令或接触真实数据库的攻击样例。

## 检查 Electron 与本机权限

- BrowserWindow 应启用上下文隔离，禁用渲染进程直接访问 Node.js；评估是否需要沙箱。
- 预加载脚本只暴露明确、最小的 API，不暴露任意文件、任意 SQL、任意 IPC 或系统命令能力。
- 主进程应验证每个 IPC 参数、调用来源、路径、金额、分类和操作权限，不能信任界面已经校验。
- 限制新窗口、外部导航、远程内容和不安全协议；不要加载未经信任的网页代码。
- 错误提示和日志不得泄露本机用户名、完整路径、SQL、账目、令牌或内部堆栈。
- 安装包应只包含运行所需文件，不包含开发数据库、备份、`.env`、源映射或测试秘密。

## 检查数据与配置安全

- 核对 SQLite 约束、外键、金额整数存储和事务边界。
- 核对备份恢复的格式校验、恢复前安全副本、失败回滚和目标文件覆盖规则。
- 核对更改数据位置时的新数据库校验、切换时机、原数据保留和不可用目录处理。
- 检查 CSV 公式注入风险：导出到表格软件时，以 `=`, `+`, `-`, `@` 开头的不可信单元格可能被当作公式。
- 检查本地数据库、备份和配置的权限说明是否与产品承诺一致；未加密的数据不能被描述为加密或绝对安全。
- 检查配置是否使用环境变量或操作系统安全存储承载真正秘密，示例值必须明显是占位符。

## 检查依赖与构建

检查 `package.json` 和锁文件中的依赖、安装脚本、过宽版本范围和已知风险。需要联网查询最新漏洞库时，先说明网络访问目的；无法联网时写明“依赖漏洞库未实时核验”，不要声称依赖绝对安全。

核对 `package.json` 的 `build.files`、图标、资源和安装目标，确认忽略目录没有被其他通配规则重新包含。构建成功不能证明安全。

## 风险分级

- **严重**：可直接导致秘密泄露、任意代码/命令执行、SQL 注入、账目破坏或任意文件覆盖。
- **高**：需要一定条件，但可能造成敏感数据泄露、权限扩大、备份破坏或安全边界绕过。
- **中**：防护不完整、错误信息过度、缺少关键验证或容易演变为漏洞。
- **低**：安全加固建议、文档与实现不一致或纵深防御不足。

同时标注证据可信度：已确认、较高可能、需要人工确认。不要把关键词命中直接宣布为已确认漏洞。

## 修复边界

默认不修改任何文件。用户要求修复时：

1. 先解释风险和可行方案；明显影响体验、兼容性、隐私或维护成本时，依照 `codex.md` 等待用户选择。
2. 优先撤销或轮换已泄露凭据；仅从当前文件删除秘密不能清除 Git 历史和已经复制出去的内容。
3. 进行最小范围修复，并使用隔离测试验证；不得用真实秘密、真实数据库或破坏性攻击验证。
4. 执行 `npm.cmd run typecheck`、`npm.cmd test`，涉及打包或 Electron 入口时再执行构建验证。
5. 未经用户明确授权，不重写 Git 历史、不删除数据、不吊销凭据、不发布或推送代码。

## 输出脱敏报告

```markdown
安全审计结论：通过 / 有风险 / 不通过 / 部分验证 / 被阻塞

- 检查范围：
- 严重：X
- 高：X
- 中：X
- 低：X
- 敏感信息候选：
- 注入风险：
- 配置风险：
- Electron 与本机权限风险：
- 数据、文件和备份风险：
- 依赖与构建风险：
- 未检查内容：
- 建议处理顺序：
```

每项发现包含严重度、可信度、文件与行号、通俗风险解释、成立条件和修复建议。不得包含完整秘密、可直接滥用的攻击命令或真实用户数据。没有发现问题时使用“在本次检查范围内未发现”，不要写“项目绝对安全”。

## 完成标准

- 敏感信息脚本已实际运行，或明确说明无法运行；
- 已人工核对脚本候选项，排除明显占位符和规则文本；
- 已检查 SQL、命令、路径、Electron IPC、配置、数据文件和构建边界；
- 报告包含证据、严重度、可信度和未检查范围；
- 没有读取真实数据库、输出秘密或执行破坏性验证；
- 已复查 Git 状态，默认没有修改产品文件。
