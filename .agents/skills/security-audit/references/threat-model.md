# 可噜记账安全审计模型

## 需要保护的内容

- 用户的人民币花销、商家、备注、日期和支付方式。
- 分类、主题、默认支付方式和数据位置设置。
- SQLite 数据库、完整备份和 CSV 导出文件。
- 用户电脑上的文件路径、用户名和操作系统信息。
- 未来可能加入的 API Key、更新签名、云同步令牌或服务凭据。
- 应用代码、构建配置和 Git 仓库访问权限。

## 主要输入入口

- 新增和编辑花销表单。
- 搜索关键词、分类名称、商家和备注。
- CSV 导入文件。
- SQLite 备份恢复文件。
- 用户选择的数据库存放目录。
- Electron IPC 参数和文件选择结果。
- 安装包内资源和未来可能加载的外部 URL。

## 主要信任边界

- React 界面不能被视为可信；主进程必须重新验证输入。
- 预加载脚本是网页界面与本机能力之间的安全闸门，应保持最小权限。
- 用户选择的 CSV、备份和目录可能格式错误、被恶意构造或突然不可用。
- SQLite 保存的是本地敏感数据，但第一版没有额外加密，只依赖 Windows 账户权限。
- GitHub 私人仓库降低公开曝光概率，但不能安全保存密码或令牌。
- 安装包会发给其他用户，任何被打包的开发数据都可能外泄。

## 项目重点检查表

### 敏感信息

- 源码和配置中没有真实密码、令牌、私钥、Cookie 或带凭据连接地址。
- `.gitignore` 排除 `.env*`、数据库、WAL/SHM、备份、日志、构建输出和本地路径配置。
- 安装包不包含开发者账目、备份或个人路径。
- 错误、日志和界面不显示完整数据库内容或秘密。

### 注入与输入验证

- 数据值通过 SQLite 参数绑定写入。
- 动态 SQL 标识符和文件路径经过白名单或可靠边界检查。
- CSV 字段不能改变 SQL、命令或导出表格行为。
- 恢复文件经过格式、表结构和版本检查。
- IPC 方法不接受任意频道、任意文件路径或任意 SQL。

### Electron

- `contextIsolation: true`。
- `nodeIntegration: false`。
- 渲染进程无法直接访问数据库和任意本机文件。
- 预加载 API 参数明确、数量有限，并由主进程复核。
- 不允许不可信导航、新窗口或脚本协议。

### 数据完整性

- 金额以正整数分存储，并有数据库约束。
- 导入和迁移使用事务或先校验后切换。
- 恢复前创建当前数据安全副本，失败时保持原数据。
- 分类变更不删除或破坏历史账目。
- 自选目录不可用时不静默写入错误位置或覆盖同名文件。

## 审计限制

静态代码审计不能独立证明以下内容：

- Windows 实际文件权限和其他本机用户能否读取数据。
- 已发布安装包是否与当前源码完全一致。
- Git 历史、他人克隆、副本和日志中是否曾经出现过秘密。
- 第三方依赖当前是否存在最新披露漏洞，除非连接实时漏洞库核验。
- 运行时竞争条件、恶意文件和异常断电下的全部行为。

报告必须列出未实际验证的项目。
